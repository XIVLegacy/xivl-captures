# Cast Property and Result Wire Order

Two retained s2c sequences in `party_battle_leve.pcapng` contain a nonzero
`castCommandClient` write, matching numeric result rows, and a later zero
`castCommandClient` write. The result source and property wrapper source are
equal in both sequences. These are connection-local wire observations.

| Witness | Nonzero command | Last matching result | Command zero |
| --- | --- | --- | --- |
| 1 | frame 814, subevent 0, record 1 | frame 822, subevent 1 | frame 823, subevent 2, record 2 |
| 2 | frame 3290, subevent 3, record 1 | frame 3297, subevent 1 | frame 3298, subevent 0, record 0 |

All locators use zero-based indices within connection 0's reconstructed s2c
stream. The command value is 27346. The first last-result row contains numeric
value 166 and text-row ID 30320. The second contains numeric value 0 and
text-row ID 30209. Each interval also contains an earlier matching result row
with text-row ID 30128 and row effect ID 1. These integers do not establish
the player's action or the producer's helper implementation.

The two nonzero command writes share their property packet with a preceding
`castEndClient` record. The retained corpus has four command records and two
deadline records for these hashes. Neither command-zero packet contains a
deadline-zero record. This does not establish a rule for all cast endings.

A numeric `0x0144` mode update immediately precedes each last matching result
row. This study assigns no chant semantics to that update. Wire order does
not establish native queue consumption, gauge visibility, or CPU execution
order.

The script consumer's conditional visibility behavior is documented in
[the cast gauge lifecycle](https://github.com/XIVLegacy/xivl-client-scripts/blob/f82d2596059f169d52684cd32e9eea8f92750436/docs/cast-gauge-lifecycle.md).
That script rule does not bind the captured actor to the local player or
determine when queued results are displayed.

The extractor scans all 54 members declared by
[the source manifest](../../sources/pcap-1.23b/manifest.yaml), admits clear game
connections through their admitted complete-frame prefixes and keeps
connection and direction boundaries intact. Prefix framing counters do not
measure discarded raw TCP tails or excluded traffic. It checks
capture hashes, framing, property-record widths, and result-row capacities.
Unsupported `0x0177` callbacks are counted without assigning meanings.

[Accounting](derived/accounting.json) retains completeness details, sanitized
witness context, actor-equality checks, and exact frame, subevent, property
record, and inflated-byte locators. [Events](derived/events.csv) and
[sequences](derived/sequences.csv) provide compact citation tables. Actor
labels encode equality only within one capture. They do not identify players
or prove that a property subject is the local player.

The [property stream catalog](../property-stream-hash-catalog/README.md)
independently retains the six numeric property records. Native name and type
resolution belongs to the
[native cast contract](https://github.com/XIVLegacy/xivl-client-structs/blob/b1b36be9678832830bcc319e50a1c061c4ffabe5/manifests/cast_chant_presentation.json#L54)
under `activeCastGauge.properties`. Result fields follow the
[battle result backfit](../battle-result-backfit/README.md).

Regenerate with `python tools/extractors/extract_cast_result_state_order.py`.
Use `--check` to compare regenerated bytes and `--public-shape` to validate
retained products without restricted raw inputs.
