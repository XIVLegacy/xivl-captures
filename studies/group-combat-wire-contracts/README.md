# Occupancy, group work, and enmity

The retained corpus contains 44 s2c `0x0187` packets in 14 captures,
275 s2c `0x017A` packets in 16 captures, and 149 s2c `0x0195` packets.
[Accounting](derived/accounting.json) pins all 54 capture members by SHA-256.
The [source manifest](../../sources/pcap-1.23b/manifest.yaml) owns the
retained input identities. Evidence class: packet-capture.

## Reproduction and order

Run `python tools/extractors/extract_group_combat_contracts.py`; add `--check`
to compare regenerated bytes. `--check --public-shape` checks retained product
accounting and public input pins without replaying capture bytes.

The extractor admits clear game connections through the canonical decoder,
checks member hashes, compression flags, complete frame extents, subevent
extents, and unused group-work capacity. It maps each frame to the first
captured TCP packet completing all its bytes. The tables order by that packet
and preserve frame/subevent order within a direction. Connection, frame, and
subevent indexes start at zero; capture packet indexes start at one.
Separate directions completing in the same packet have no inferred order.
The [combat timeline](derived/combat-timeline.csv) preserves selected command,
result, group, occupancy, and indicator events without collapsing repetitions.

## Occupancy `0x0187`

Offsets below start after the 16-byte game-message prefix and exclude the
16-byte subevent header. Every observed subevent is 96 bytes, with a 64-byte
application payload. The static layout and route are recorded by
`xivl-client-structs:manifests/unmapped_payload_decoding.json#s2c_0x0187`
and `xivl-client-structs:manifests/director_group_wire_identity.json`.

| Offset | Width | Field and retained values |
| --- | --- | --- |
| `0x00` | 8 | Group reference pair, emitted as `group_pair_0`; components remain opaque. |
| `0x08` | 4 | Header value 10001, 10002, 50001, or 80001; semantics remain bounded to the Group header. |
| `0x0c` | 4 | Unknown, always zero. |
| `0x10` | 4 | First occupancy-work component: zero or 7858604. |
| `0x14` | 4 | Second occupancy-work component: zero or 2147483648. |
| `0x18` | 4 | Localized name id, always 4294967295. |
| `0x1c` | 36 | Occupancy name storage, entirely zero in all retained packets. |

[Occupancy rows](derived/occupancy.csv) retain every field. There are 35
zero work pairs and nine `(7858604, 2147483648)` pairs. Combining the latter
as little-endian u64 gives 9223372036862634412. The table records equality
with same-connection `0x017C` group references at application `0x18`/`0x28`
and their group types. Seven nonzero pairs join a type-10001 header while
their occupancy group joins type 10002. The two remaining nonzero pairs
have no same-capture header witness. [Group matches](derived/group-matches.csv) records
the exact packet locators and offsets of equal eight-byte values in
`0x017C`-`0x0186`. Numeric equality does not establish ownership policy.
The autoattack and skills examples contain no matching group-header specimen
for their occupancy group reference; a header from another capture is not
silently substituted.

In `combat_autoattack.pcapng`, the first `0x0139` at frame 7/subevent 1 is a
self-target result with message id zero. The two occupancy packets are at
frame 19/subevents 0 and 1, followed by the first damage result at frame
20/subevent 1, message 30301. Frames 19 and 20 complete in capture packet
65; frame 7 completes in packet 20. Thus occupancy precedes the first damage
result, although it follows an earlier non-damage `0x0139`. The pair changes from zero work to the nonzero
reference. No `0x0143` occurs before this capture ends.

`party_battle_leve.pcapng` starts with an earlier party occupancy packet at
frame 65. The first type-10002 occupancy pair is frame 373/subevents 0 and
1, completing in capture packet 576. The first admitted damage result is
frame 395/subevent 0 in packet 587, after that pair. Twelve occupancy
packets cover six distinct group references. Five type-10002 references
receive zero/nonzero pairs; the party reference receives its own updates.
Seven `0x0143` events occur later, starting at frame 848/subevent 1.
[Deletion tuples](derived/deletions.csv) show that the first five have their
first three qwords zero and the fourth equal to each of the five type-10002
occupancy references. These follow their corresponding occupancy pairs.
The last two carry another group reference. This establishes a bounded
same-group deletion sequence without proving that the trigger is disengagement.
The repeated group references do not prove one occupancy packet per target.

## Group work `0x017A`

Every subevent is 176 bytes, with a 144-byte application payload. Bytes
`0x00`-`0x07` carry the group reference, byte `0x08` gives the stream byte
count, and `0x09`-`0x8f` provide 135 bytes of capacity for tagged properties
and target markers. The byte count is not a record count. A typed property
uses a width byte, little-endian u32 property id, and that many value bytes.
The native consumer is `FUN_006C96B0` through `FUN_006C84A0`, recorded by
`xivl-client-structs:manifests/party_subsystem.json#0x017A` and
`xivl-opcodes:data/client_opcode_semantics.json#s2c-017a`.

[Group work](derived/group-work.csv) records every occurrence, record count,
later same-group packets, and target marker. The
[property table](derived/group-work-properties.csv) contains all 338 typed
properties. No name or scalar rank is guessed from a property hash.
The maximum observed stream byte count is 47 and maximum property count is
six. Every observed target marker is `0x82 + ASCII-length`, with tags
`0x88`, `0x97`, `0x9a`, or `0x9b`. There is no observed alternative marker
class or payload-capacity split. Repeated same-group updates alone are not
continuation evidence.

The [group headers](derived/group-headers.csv) contain no type-20002
player-linkshell group. Login carries party and type-80001 work; the invite
example carries type-30001 work. Neither establishes large-linkshell member
rank chunking. The full payload's capacity is established, but no maximum
linkshell membership or universal continuation rule follows from it.

The client rank consumer is documented in
`xivl-client-scripts:docs/linkshell-party-command-contracts.md`, section
"CompanyGroup rank consumer": `getMemberRank` resolves a member index and
reads `work._memberSave[index].rank`, declared as an 8-bit integer. Calling
it for the local player uses that same member array. The separate
`work._globalSave.rank` is a company rank, not an established recipient-rank
field. A native property-hash join from this structure to a linkshell
`0x017A` stream remains unestablished in these captures.

The native parser's marker classes, persistent continuation state, completion
callback and type-20002 rank consumer inventory are recorded in
`xivl-client-structs:docs/linkshell-rank-work-contract.md`.
That static record does not add a retained linkshell or `0x62` specimen here.

The [master-transfer capture boundary](linkshell-master-transfer.md) records
the full-corpus request search, group-type census, source pins and reproduction
method. It identifies no transfer request/reply specimen.

## Enmity `0x0195`

Every subevent is 40 bytes. The eight-byte application payload contains a
u32 target actor at `0x00`, a u16 indicator value at `0x04`, and a two-byte
zero tail at `0x06`. The receiver layout is recorded by
`xivl-client-structs:manifests/s2c_payload_decoding_lua_bound.json#s2c_0x0195`.
[Enmity rows](derived/enmity.csv) retain every event, target/value changes,
and the immediately preceding same-connection s2c action result. That result
can concern another actor and is context, not a causal join.

Both combat examples carry four indicators for one wrapped source actor:

| Capture | Frames | Target sequence | Value sequence |
| --- | --- | --- | --- |
| `combat_autoattack.pcapng` | 26, 27, 115, 116 | 3758096384, 43723073, 43723073, 3758096384 | 100, 100, 65535, 65535 |
| `combat_skills.pcapng` | 32, 33, 75, 76 | 3758096384, 43723073, 43723073, 3758096384 | 100, 100, 65535, 65535 |

The amount remains unchanged when the target first changes to the player;
it changes once to 65535 before the target returns to 3758096384.
Intermediate damage results have no corresponding indicator packet. These
examples establish neither a per-hit send rule nor a periodic cadence.
Across the full retained corpus the non-sentinel values fall within 1-100,
while 65535 also occurs. This range and co-occurrence do not prove percentage,
rank, flag semantics, a normalization formula, or the meaning of either
sentinel. Those meanings remain unknown here.
