# Battle Result Backfit

## Study contents

This active study backfits the clientbound battle-result family `0x0139`
through `0x013C` into one row-oriented packet evidence set. Stage 1 decoded all
531 retained family packets into 622 target rows, preserved deterministic
capture-local order, and joined nonzero message IDs to the 1.23b
`worldMaster.csv` namespace. The generic wire value remains `numeric_value`;
it is not renamed damage, healing, or another behavior without message evidence.

| Stage | Status | Result |
|---|---|---|
| 1. Decode and accounting | complete | 531 packets, 622 rows, zero source-ID or row-count/target-count invariant failures |
| 2. Distribution analysis | complete | Outcome distributions and strict command/source/target comparison sets are recorded |
| 3. Competing model fits | pending | DEF/VIT, critical, block, and Cure hypotheses remain unfit |
| 4. Promotion decision | pending | No runtime formula or tuning value is promoted |

## Source material

- `sources/pcap-1.23b/manifest.yaml` supplies the 53 game-protocol captures and
  their scenario membership. `login.pcapng` remains excluded because it is TLS.
- The explicit field-model input supplies the static 0x0139-0x013C wire shapes,
  capacities, and field boundaries.
- The explicit client-data input supplies `csv/worldMaster.csv` for localized
  row identity and `derived/command_battle_params.csv` to validate that command
  row 27346 is Cure. Command joins otherwise prove table identity only.
- `derived/accounting.json` records the SHA-256 of every capture and all three
  cross-repository inputs used for this generation.

The extractor reconstructs TCP lanes, parses outer frames, inflates zlib bodies,
and walks wrapped actor subevents. The application payload begins after the
8-byte inner header and 8-byte game-message prefix. X10 and X18 rows are
transposed from structure-of-arrays wire storage; X18 has a static shape but no
retained packet, and X00 carries no target rows.

## Promoted conclusions

Stage 1 promotes only an evidence table and accounting facts:

- 0x0139: 438 packets and 438 rows.
- 0x013A: 66 packets and 184 rows.
- 0x013B: 0 packets and 0 rows.
- 0x013C: 27 packets and 0 rows.
- Cure command row 27346 appears in eight decoded rows; exactly three join to
  the HP-recovery message, with observed numeric values 151, 152, and 166.

Message class is assigned only by exact `worldMaster` row identity. The retained
corpus contains normal damage, critical damage, blocked damage, parried damage,
miss, HP recovery, non-fit, and unclassified rows. Numeric magnitude and
effect IDs never select a class.

## Evidence gaps

- Actor IDs remain numeric. The selected products contain no actor-name, level,
  VIT, DEF, weapon, class, or target-stat normalization table.
- `command_id` joins prove table identity, not command behavior, scaling,
  status application, or final damage calculation.
- `numeric_value` is a widened wire u16 with generic consumer use.
  `effect_id` and `effect_or_animation_id` are not outcome classifiers.
- Wire order is deterministic within capture and connection blocks. It is not a
  capture-wide arrival timeline, and the outer header's 8-byte field is not
  interpreted.
- The raw outer-header 8-byte field is retained as `outer_timestamp_or_seq_hex`
  but is not interpreted as a wall-clock timestamp or used for cross-lane order.
- The corpus is a set of gameplay witnesses, not a controlled rate or formula
  experiment.
